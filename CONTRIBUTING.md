# Вклад в NOX Vault

Спасибо за интерес к проекту! NOX Vault работает с секретами пользователей, поэтому
главный принцип изменений: **не ослаблять криптографию, не расширять поверхность атаки
и не добавлять сетевые зависимости без очень веской причины**.

## Перед началом

- Прочитайте [README](README.md), [формат контейнера](docs/FORMAT.md) и
  [модель безопасности](docs/SECURITY.md).
- Для крупной функции сначала откройте issue и опишите сценарий пользователя,
  угрозы и влияние на формат хранилища.
- Никогда не прикладывайте к issue или pull request настоящие `.nox`, CSV с паролями,
  мастер-пароль, ключ восстановления, ключи подписи или скриншоты с реальными секретами.

## Локальная среда

Требуются Android Studio, JDK 17 и Android SDK 35.

Проверка перед pull request:

```bash
./gradlew :app:testDebugUnitTest
./gradlew :app:compileDebugAndroidTestKotlin
```

На Windows используйте `gradlew.bat` вместо `./gradlew`.

Инструментальные тесты на реальном устройстве запускайте только осознанно:
они работают с файлами приложения тестового устройства. Перед этим сделайте копию
`.nox` настоящего хранилища.

## Принципы кода

- Kotlin + Jetpack Compose; UI не обращается напрямую к файлам и криптографии.
- Все операции с хранилищем проходят через `VaultRepository`.
- Никаких самодельных криптографических алгоритмов. Используйте проверенные
  AES-GCM, Argon2id/PBKDF2, Android Keystore и `SecureRandom`.
- Никаких секретов в LogCat, исключениях, аналитике, временные открытые файлы
  и Intent extras между экранами.
- Сохраняйте приложение полностью офлайн: не добавляйте разрешение `INTERNET`,
  трекеры, рекламу и удалённую конфигурацию.
- Изменения формата контейнера должны быть обратно совместимы или иметь явную
  миграцию и тесты на старых данных.
- Для новой логики добавляйте unit-тесты; для исправления бага — тест, который
  падает до исправления, если это технически возможно.
- Комментарии к нетривиальной логике — на русском, как в существующем коде.

## Pull request

В описании укажите:

1. Что изменилось и зачем.
2. Как это влияет на безопасность и совместимость формата.
3. Какие тесты запущены и их результат.
4. Скриншоты только с вымышленными тестовыми данными, если менялся интерфейс.

Небольшие сфокусированные pull request проверять заметно легче, чем один огромный.
