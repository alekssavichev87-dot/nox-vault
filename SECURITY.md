# Политика безопасности

## Поддерживаемые версии

Исправления безопасности планируются для последней опубликованной версии.
Для старых версий рекомендуется обновление после создания и проверки резервной
копии `.nox`.

| Версия | Поддержка |
|---|---|
| Последняя 1.2.x | ✅ |
| Старые версии | ❌ |

## Как сообщить об уязвимости

Пожалуйста, **не открывайте публичный GitHub Issue** с работающим эксплойтом,
реальным содержимым хранилища или способом обхода шифрования.

Предпочтительный способ — приватное сообщение владельцу репозитория через
GitHub Security Advisories / Private Vulnerability Reporting, если эта функция
включена на вкладке **Security**. Если она недоступна, свяжитесь с владельцем
репозитория приватно через GitHub, не публикуя детали уязвимости.

В сообщении по возможности укажите:

- версию NOX Vault;
- модель устройства и версию Android;
- шаги воспроизведения на тестовом, не настоящем хранилище;
- ожидаемый и фактический результат;
- возможное влияние: раскрытие, подмена, повреждение или потеря данных.

## Что никогда нельзя присылать

- мастер-пароль;
- ключ восстановления;
- файл настоящего хранилища или резервной копии `.nox`;
- CSV с настоящими паролями;
- ключи подписи приложения;
- скриншоты и логи с реальными секретами.

Для воспроизведения создайте отдельное тестовое хранилище с вымышленными данными.

## Область рассмотрения

Особенно важны сообщения о:

- получении открытых секретов без мастер-пароля, ключа восстановления или успешной
  биометрии;
- подмене зашифрованного контейнера без обнаружения GCM;
- утечке секретов в логи, буфер обмена сверх настройки, автозаполнение чужой цели
  без выбора пользователя или незашифрованные временные файлы;
- повреждении или потере хранилища при обычной атомарной записи;
- обходе автоблокировки или authenticated autofill flow.

Проект не проходил независимый аудит и не предлагает bug bounty. Модель угроз и
известные ограничения подробно описаны в [docs/SECURITY.md](docs/SECURITY.md).
