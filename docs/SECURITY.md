# Модель безопасности, риски и ограничения NOX Vault 1.2

## Что приложение защищает и чем

| Угроза | Защита |
|---|---|
| Кража файла хранилища / резервной копии | AES-256-GCM; ключ из пароля — Argon2id (64 МиБ, t=3). Стойкость = стойкость вашего мастер-пароля к офлайн-перебору. Используйте длинную фразу (14+ символов, лучше 4–5 слов). |
| Подмена/повреждение данных | Тег подлинности GCM на payload и на каждом слоте ключа; AAD разделяет контексты слотов. |
| Подсматривание через интерфейс | FLAG_SECURE (нет скриншотов и превью в недавних приложениях), автоблокировка в фоне, растущая пауза после 5 неверных паролей, опциональное удаление после 10. |
| Чужие облачные копии | `allowBackup=false` + правила исключения из cloud-backup и device-transfer. Разрешения INTERNET у приложения нет вообще. |
| Секреты в логах/аналитике | Логов с данными нет, SDK аналитики нет, сети нет. |
| Буфер обмена | Метка «чувствительное» (Android 13+), автоочистка через заданное время, только если содержимое не успели заменить. |
| Автозаполнение | Выключено по умолчанию и включается двумя отдельными переключателями: в NOX Vault и в настройках Android. При заблокированном хранилище служба не расшифровывает данные в фоне, а ведёт на обычный экран разблокировки; разовый вход ради автофилла снова блокирует хранилище после выбора. Значения чужих полей не читаются и не сохраняются. |
| Забытый пароль | Ключ восстановления (256 бит) — второй независимый слот. Хранить офлайн отдельно от телефона. |
| Прерванная запись/сбой питания | Атомарное сохранение + предыдущая хорошая версия `.bak` с автовосстановлением. |

## Чего приложение НЕ обещает

- **Скомпрометированное устройство**: root, вредоносное ПО с правами чтения экрана/памяти,
  кейлоггер, чужая клавиатура, физический доступ к РАЗБЛОКИРОВАННОМУ телефону — против этого
  не защитит ни один менеджер паролей. Держите систему обновлённой, ставьте приложения из проверенных источников.
- **Память процесса**: пока хранилище открыто, расшифрованные данные и ключ находятся в RAM.
  При блокировке массивы ключей затираются (best-effort), но JVM/Android не гарантируют полное
  отсутствие копий строк пароля в куче (строки из полей ввода Compose неизменяемы).
- **Буфер обмена**: в течение заданных секунд секрет доступен приложениям, читающим буфер.
- **Импорт CSV из браузера**: исходный файл содержит ВСЕ пароли в открытом виде и находится вне
  контроля приложения (Загрузки, компьютер, кабель). Приложение читает его только в память,
  не копирует и не логирует, сессия импорта очищается при блокировке; но удалить сам файл —
  обязанность пользователя. Не пересылайте CSV через мессенджеры/облака.
- **Автозаполнение показывает секреты целевому приложению по вашему выбору**: если вы сами
  выбрали запись на фишинговом сайте или в поддельном приложении, Android вставит значения
  именно туда. Подбор по домену/имени приложения — эвристика, а не доказательство подлинности;
  перед выбором проверяйте адрес сайта на экране выбора и в браузере. Пока хранилище уже
  разблокировано, прямые подсказки могут показывать название записи и логин (не пароль) в
  системном списке над формой. Если это нежелательно — держите автоблокировку короткой или
  выключите автофилл.
- **Пауза после неверных попыток** хранится в обычных настройках: атакующий с файлом может
  сбросить счётчик и перебирать пароль офлайн. Это замедление интерфейса, а не криптозащита —
  криптозащиту даёт Argon2id + длинный пароль.
- **Опция «удалить после 10 ошибок» опасна**: любой человек с телефоном в руках уничтожит ваши
  данные за минуту. Включайте только при наличии свежей копии .nox вне телефона.
- Биометрия зависит от сенсоров и Keystore конкретного устройства и **никогда не является
  единственным доступом**: мастер-пароль и ключ восстановления работают без неё.

## Автоматические тесты: что покрыто

Unit (JVM, запускаются `testDebugUnitTest`): AES-GCM roundtrip/неверный ключ/подмена/AAD,
Argon2id и PBKDF2, ключ восстановления, полный цикл контейнера (создание, неверный пароль,
восстановление, повреждение, бэкап/импорт, смена пароля, отсутствие открытых секретов в файле),
генератор паролей, поиск и превью без секретов, импорт CSV браузеров (форматы, кавычки,
кодировки, дубликаты), порционное чтение вложений с лимитом размера, а также подбор записей и
классификацию полей для автозаполнения. Всего 60 тестов.

Инструментальные (нужен телефон/эмулятор, `connectedAndroidTest`): цикл через реальные файлы,
сохранение после «перезапуска», восстановление из `.bak` при повреждённом основном файле,
экспорт/импорт на «чистую установку», полное удаление.

Вручную стоит проверить на вашем устройстве: биометрию (включение, вход, поведение после
сброса отпечатков в настройках телефона), автоблокировку при сворачивании, очистку буфера,
работу без биометрии (устройства без датчика/без зарегистрированного отпечатка), а также
автозаполнение в браузере и в одном приложении — при разблокированном и закрытом хранилище.

## Перед хранением действительно важных секретов

1. Создайте хранилище, запишите ключ восстановления на бумаге, держите отдельно от телефона.
2. Сразу сделайте копию .nox с отдельным паролем; файл и пароль — в разных местах.
3. Проверьте восстановление: на эмуляторе/втором устройстве импортируйте копию.
4. Помните: успешные тесты ≠ аудит. Проект не проходил независимый аудит безопасности;
   для критически важных данных рассмотрите аудит кода специалистом и/или проверенные временем
   решения (KeePassDX и т. п.) как минимум для дублирования.
5. Release-сборка в v1 без минификации (R8 выключен сознательно). Перед включением —
   прогнать все тесты на release-артефакте (правила уже лежат в `app/proguard-rules.pro`).
